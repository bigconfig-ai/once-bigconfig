BigConfig manual

Three nested libraries — Selmer (Django-style template engine), BigConfig (workflow + render engine), and Once (infrastructure-automation CLI) — each implemented three times in TypeScript, Python and Clojure with a shared public surface. Pick a language at the top; the manual rewrites itself.

TypeScript Python 3.12+ Clojure / Babashka OpenTofu Ansible Selmer EPL-1.0 · MIT

Overview

This is a polyrepo of nine projects arranged as three concentric layers:

Selmer

Template engine

A fast, Django-inspired template system. Variables, filters, tags, template inheritance, custom delimiters. Originally yogthos/Selmer in Clojure; Python and TypeScript are stdlib-only ports that mirror the public surface.

BigConfig

Workflow + render engine

Threads an opts map through ordered steps. Adds Git-tag pessimistic locking, a Selmer-based file-tree renderer, a swap-able shell runner, and the big-tofu construct helpers for OpenTofu. Consumes Selmer.

Once

Infra automation CLI

An opinionated cloud-provisioning + ONCE-deployment pipeline. Orchestrates OpenTofu through six stages, then hands off to Ansible. Profiles select the cloud (DigitalOcean / hcloud / OCI / no-infra) and the apps to deploy. Consumes BigConfig.

The repo layout is one project per language per leaf:

bigconfig/
├── selmer/{clojure,python,typescript}      # Django-style template engine
├── big-config/{clojure,python,typescript}  # Workflow + render engine (uses selmer)
└── once/{clojure,python,typescript}        # Infra automation CLI (uses big-config)

Each leaf is an independent project with its own build system, tests and CLAUDE.md. The root is not a git repo — it is a workspace that holds the nine side-by-side so they can reference each other by relative path during development.

Naming at boundaries Even though Python and TypeScript pick idiomatic identifiers for their own code, kebab-case string keys are preserved verbatim at the data layer. The reserved engine key "big-config/exit" stays exactly that across all three languages — it's never converted to big_config__exit or bigConfigExit. Same for profile / template parameters: "provider-compute", "do-token", "oci-shape". This is what makes the three implementations interchangeable across the wire.

Selmer

template engine

A fast, Django-inspired template system. Variables, filters, tags, template inheritance, includes, validation, caching, custom tags and custom filters. The Clojure implementation is the upstream reference; Python and TypeScript are dependency-free ports that preserve the public surface.

  • Variables: {{ name }}, dotted paths ({{ foo.bar.0.baz }}); double-dot escapes namespaced keys ({{ foo..bar/baz }}).
  • Filters: {{ name|upper }}, chainable.
  • Tags: {% if %}, {% for %}, {% block %}, {% extends %}, {% include %}, and ~20 others.
  • Custom delimiters so a template emitting Ansible's own {{ ... }} can pass through untouched (used by BigConfig).

Quick start

import { render, renderFile, addFilter, addTag } from "selmer";

// 1. Inline render
render("Hello, {{ name|upper }}!", { name: "world" });
// => "Hello, WORLD!"

// 2. File render
renderFile("page.html", { user: { name: "Ada" } });

// 3. Custom filter
addFilter("shout", (v: string) => v.toUpperCase() + "!");
render("{{ x|shout }}", { x: "hi" });   // => "HI!"

// 4. Custom tag
addTag("now", (args, ctx) => new Date().toISOString());
render("It is {% now %}", {});
from selmer import render, render_file, add_filter, add_tag

# 1. Inline render
render("Hello, {{ name|upper }}!", {"name": "world"})
# => "Hello, WORLD!"

# 2. File render
render_file("page.html", {"user": {"name": "Ada"}})

# 3. Custom filter
add_filter("shout", lambda v: v.upper() + "!")
render("{{ x|shout }}", {"x": "hi"})   # => "HI!"

# 4. Custom tag
from datetime import datetime
add_tag("now", lambda args, ctx, _content=None: datetime.now().isoformat())
render("It is {% now %}", {})
(require '[selmer.parser :as p]
         '[selmer.filters :refer [add-filter!]])

;; 1. Inline render
(p/render "Hello, {{ name|upper }}!" {:name "world"})
;; => "Hello, WORLD!"

;; 2. File render
(p/render-file "page.html" {:user {:name "Ada"}})

;; 3. Custom filter
(add-filter! :shout (fn [v] (str (.toUpperCase v) "!")))
(p/render "{{ x|shout }}" {:x "hi"})        ;; => "HI!"

;; 4. Custom tag
(p/add-tag! :now (fn [args context-map]
                  (str (java.time.Instant/now))))
(p/render "It is {% now %}" {})

Template language

Variables

Variables are referenced with {{ name }}. Dotted paths drill into nested objects / dicts / maps:

{{ user.name }}
{{ items.0.title }}                 {# index into a sequence #}
{{ foo..bar/baz }}                  {# double-dot escapes a slash for namespaced keys #}

Filters

Filters transform a value, chain left-to-right with |:

{{ title|upper|truncate:20 }}
{{ price|currency-format:"USD":"US" }}
{{ posts|length }}
{{ user.email|default:"unknown@example.com" }}

Tags

Tags are written between {% %}. Block tags have a matching {% endTAG %}:

{% if user.is_admin %}
  Welcome, admin.
{% elif user.logged_in %}
  Welcome back, {{ user.name }}.
{% else %}
  Please sign in.
{% endif %}

{% for post in posts %}
  <li>{{ post.title }} ({{ forloop.counter }} of {{ forloop.length }})</li>
{% empty %}
  <li>No posts.</li>
{% endfor %}

The {% for %} tag exposes a forloop binding inside its body with the following counters: counter0, counter, revcounter0, revcounter, first, last, length, previous, parentloop.

Template inheritance

extends + block for layouts, include for partials:

{# base.html #}
<html><head><title>{% block title %}default{% endblock %}</title></head>
<body>{% block content %}{% endblock %}</body></html>

{# page.html #}
{% extends "base.html" %}
{% block title %}Posts{% endblock %}
{% block content %}
  {% include "partials/posts.html" %}
{% endblock %}

Custom delimiters

Selmer's most-used escape hatch: re-bind the tag/filter delimiters per render. BigConfig leans on this hard — it switches variables to <{ var }> so downstream Ansible's literal {{ ... }} passes through untouched.

import { render } from "selmer";

render(
  "Hello, <{ name|upper }>! And literal: {{ kept }}",
  { name: "world" },
  { tagOpen: "<", tagClose: ">", filterOpen: "{", filterClose: "}" }
);
// => "Hello, WORLD! And literal: {{ kept }}"
from selmer import render

render(
    "Hello, <{ name|upper }>! And literal: {{ kept }}",
    {"name": "world"},
    tag_open="<", tag_close=">",
    filter_open="{", filter_close="}",
)
# => "Hello, WORLD! And literal: {{ kept }}"
(require '[selmer.parser :as p])

(p/render "Hello, <{ name|upper }>! And literal: {{ kept }}"
           {:name "world"}
           {:tag-open    \<
            :tag-close   \>
            :filter-open \{
            :filter-close \}})
;; => "Hello, WORLD! And literal: {{ kept }}"
Why this matters Once's templates (in src/resources/.../tools/) contain BOTH <{ provider-compute }> placeholders (interpreted by Selmer at render-time) and literal {{ ansible_host }} tokens (interpreted by Ansible later). Custom delimiters keep the two passes from colliding.

Extensibility

Add a global filter

addFilter("truncate", (v: string, n: number) =>
  v.length > n ? v.slice(0, n) + "…" : v);

render("{{ title|truncate:10 }}", { title: "hello-world" });
// => "hello-worl…"
add_filter("truncate", lambda v, n: v[:int(n)] + "…" if len(v) > int(n) else v)

render("{{ title|truncate:10 }}", {"title": "hello-world"})
# => "hello-worl…"
(add-filter! :truncate
              (fn [v n]
                (let [n (Integer/parseInt (str n))]
                  (if (> (count v) n)
                    (str (subs v 0 n) "…")
                    v))))

(p/render "{{ title|truncate:10 }}" {:title "hello-world"})
;; => "hello-worl…"

Add a global tag (with an end tag, i.e. a block)

addTag("reverse", (args, context, content) => {
  const rendered = content?.["reverse"] ?? "";
  return [...String(rendered)].reverse().join("");
}, "endreverse");

render("{% reverse %}hello{% endreverse %}", {});
// => "olleh"
def reverse_tag(args, context, content=None):
    rendered = (content or {}).get("reverse", "")
    return rendered[::-1]

add_tag("reverse", reverse_tag, "endreverse")
render("{% reverse %}hello{% endreverse %}", {})
# => "olleh"
(p/add-tag! :reverse
            (fn [args context-map content]
              (apply str (reverse (get-in content [:reverse :content]))))
            :endreverse)

(p/render "{% reverse %}hello{% endreverse %}" {})
;; => "olleh"

Inline (per-render) tags and filters

Pass customTags / custom_tags / :custom-tags and customFilters / custom_filters / :custom-filters in the opts map. Inline registrations override globals for that single render call only.

Custom resource loader

Override how templates are loaded from disk (handy for sandboxing or pulling templates from an asset bundle / database):

setResourceLoader((path) => assetBundle.get(path));
set_resource_loader(lambda path: asset_bundle.get(path))
;; Clojure: override via the dynamic var `selmer.util/*custom-resource-path*`
;; or by passing :custom-resource-path in render opts.

Caching & validation

Caching is on by default in Clojure (off by default in Python/TS). Cached templates are keyed by path; render-file invalidates entries by file last-modified stamp.

cacheOn();             // enable
cacheOff();            // disable + clear
clearCache();          // just clear
cache_on()             # enable
cache_off()            # disable + clear
clear_cache()          # just clear
(cache-on!)             ;; enable (default)
(cache-off!)            ;; disable + clear
(clear-cache!)          ;; just clear

Validation runs at parse time and rejects templates that reference unknown tags or filters. Disable when porting tag handlers in-flight:

validateOff();
validate_off()
# Or catch the exception:
from selmer import SelmerValidationError, validate
try:
    validate("{% unknown_tag %}")
except SelmerValidationError as e:
    print(e.data["error_template"])
(validate-off!)

Internal seams worth knowing

Most users will never reach for these, but they're public:

AST node types

Templates parse into a list of TextNode (literal text) and FunctionNode (compiled tag/filter handlers). The protocol/interface is uniform:

  • Clojure — selmer.node/INode protocol with render-node(context-map), implemented by TextNode and FunctionNode. AOT-compiled (:deps/prep-lib) so the namespace can be used as a Git dep.
  • Python — selmer.node.TemplateNode protocol with render_node(context: Context) -> Any; TextNode and FunctionNode are dataclasses.
  • TypeScript — TemplateNode interface in src/types.ts with renderNode(context: Context) -> unknown; TextNode and FunctionNode are classes.

Global registries

The tag/filter registries are mutable maps. You can introspect them at runtime:

  • Clojure: selmer.tags/expr-tags (atom), selmer.tags/closing-tags (atom), selmer.filters/filters (atom).
  • Python: selmer.tags.expr_tags, selmer.tags.closing_tags, selmer.filters.filters.
  • TypeScript: exprTags, closingTags, filters Maps in their respective modules.

HTML safe values

Mark a value as already-safe to skip auto-escaping at the boundary:

import { SafeValue, safe } from "selmer";
render("{{ html }}", { html: safe("<em>hi</em>") });
from selmer import safe, SafeValue
render("{{ html }}", {"html": safe("<em>hi</em>")})
;; The {% safe %} tag and the |safe filter are the idiomatic Clojure form.
(p/render "{{ html|safe }}" {:html "<em>hi</em>"})

Clojure-only conveniences Clojure only

The << macro

Capture lexical bindings into a template string:

(require '[selmer.parser :refer [<<]])

;; => "Hello, world!"

set-closing-tags!

Extend the closing-tag table when registering a new block tag with non-standard endings.

BigConfig

workflow + render engine

BigConfig is the engine. It threads an opts map through a sequence of steps, captures stdout/stderr/exit-code from shell commands, renders template trees through Selmer, and provides Git-tag pessimistic locking and OpenTofu construct helpers.

Three implementations, one shape. Steps are plain functions of opts → opts; failure is reported in two reserved keys (big-config/exit and big-config/err) — not via exceptions.

Concepts

The opts map

Everything happens through a single mutable-by-rebinding map. Step functions take it as their only argument and return an updated version. Keys are namespaced strings; reserved names live under big-config/, big-config.workflow/, big-config.render/, big-config.run/, etc.

Workflows are state machines

create-workflow / workflow / createWorkflow builds a state machine where each step is a node and the transition is computed by a wire function. The engine loops until it hits the last step, accumulating opts.

Pipelines compose workflows

The "star" variants (create-workflow-star / workflow_star / createWorkflowStar) take an ordered list of [step-name, [args-string, opts-fn]] tuples and chain registered sub-workflows. Each tuple's opts-fn transforms the opts before that step runs — this is where parameter extraction from previous-stage outputs happens.

Failure is data, not exceptions

Step functions don't throw; they set big-config/exit to a non-zero integer and put a human-readable message under big-config/err. Exceptions caught by the core loop are converted into the same shape, with the stack trace under big-config/stack-trace.

Side effects are seams

Anything that touches the OS is reached through a pluggable function:

  • Shell commands go through runner (swap for a fake in tests).
  • Step dispatch goes through handle-step (plug in alternate handlers per step).
  • Templates are loaded through Selmer's setResourceLoader hook when needed.

Reserved opts keys

Every namespaced key the engine reads or writes. Keys are preserved verbatim across all three languages — these are strings, not idiomatic identifiers.

CLI argument parser

parse-args recognises a fixed set of step names — lock, git-check, render, create, build, delete, validate, describe, exec, git-push, unlock-any — and accumulates them under big-config.workflow/steps. Anything after -- becomes one raw shell command; unknown tokens are interpreted as tool:subcommand (the colon is replaced by a space).

Renderer

The render step copies template trees under big-config.workflow/prefix (default .dist/) with Selmer-rendered placeholders. Each template spec describes one tree:

Transform entries

Each entry is [source, target?, files?, …opts]:

  • source — a relative subdirectory under template, a function, or a literal map of {src → dst}.
  • target — optional sub-path under target-dir.
  • files — optional {from → to} rename map; nil copies everything.
  • …opts — flags like :raw (skip rendering) or :only (require a match), plus the per-render Selmer delimiter map.

Selmer delimiters in BigConfig

The renderer wires Selmer with non-default delimiters so that file content reads <{ var }> — leaving downstream Ansible/Jinja {{ var }} alone. The standard configuration is:

{ tag-open: "<",  tag-close: ">",
  filter-open: "{",  filter-close: "}" }

This map is passed as the delimiter element in transform entries. Once applies it on every render step (see once/{python,typescript,clojure}/src/.../tools.{py,ts,clj}).

Locking

BigConfig's locking is Git-tag pessimistic: a workflow acquires a tag named LOCK-<hash> on the remote, encoding the owner identity in the tag message. A second process attempting to push the same tag fails; if it does succeed, it cross-checks the remote and either continues or backs off.

Workflows

  • lock — Acquire. Steps: generate-lock-id → delete-tag → create-tag → push-tag → (success ? end : get-remote-tag → read-tag → check-tag → end).
  • unlock-any — Force-release. No ownership check. Steps: generate-lock-id → delete-tag → delete-remote-tag → check-remote-tag → end.

Inputs

KeyMeaning
big-config.lock/ownerRequired. String identifying who is taking the lock.
big-config.lock/lock-keysArray of opts keys hashed into the lock identity (so different param sets get different locks).

Outputs

lock-name (tag), lock-details (encoded body), tag-content (remote body when checking). Failure flows through big-config/exit and big-config/err as usual.

Once

infra automation CLI

Once is the outermost layer: an opinionated CLI that takes a profile, provisions cloud infrastructure with OpenTofu, configures it with Ansible, and deploys Basecamp ONCE applications onto it. Built on BigConfig (workflow engine + renderer), which is in turn built on Selmer.

One command (once package create) runs the full lifecycle. Profiles are plain map/dict/object literals composed from sub-profiles; you change provider by editing one line of options.{py,ts,clj}.

function compose(...layers: Profile[]): Opts {
  let params: Record<string, any> = {};
  let profile: string | undefined;
  for (const layer of layers) {
    if (layer.profile !== undefined) profile = layer.profile;
    params = { ...params, ...layer.params };
  }
  return syncAliases({ [PROFILE]: profile, [PARAMS]: params });
}

Parameter system

Each render step needs a parameter map. Once layers parameters in three passes:

  1. Profile defaults — what options.{py,ts,clj} declares under params.
  2. BC_PAR_* env overrides — applied by workflow/read-bc-pars.
  3. Tofu-output extracts — each stage reads outputs of earlier stages and merges them in.

The composition lives in params.{py,ts,clj}:

export function optsFn(opts: Opts): Opts {
  return syncAliases(
    tofuParams(
      tofuSmtpParams(
        bcWorkflow.readBcPars(toBcOpts(opts))
      )
    )
  );
}
def opts_fn(opts: Opts) -> Opts:
    return sync_aliases(
        tofu_params(
            tofu_smtp_params(
                bc_workflow.read_bc_pars(to_bc_opts(opts))
            )
        )
    )
(def opts-fn (comp tofu-params tofu-smtp-params workflow/read-bc-pars))

Read right-to-left: first read-bc-pars pulls BC_PAR_* env vars, then tofu-smtp-params extracts SMTP records from the previous SMTP stage's Tofu output, then tofu-params extracts compute outputs (IP, sudoer, uid). The result becomes the params for the next stage.

Fallback values

When a stage runs before its inputs are available (e.g. you're rendering ansible templates without having applied tofu yet), the params extractor falls back to placeholder values: ip = "192.168.0.1", sudoer, uid, name, user for compute, and provider-specific credentials for SMTP. See fallback-compute-params / fallbackComputeParams / fallback_compute_params.

  • BC_PAR_PROVIDER_BACKEND={s3|r2|local} — routes remote state to the chosen backend; matches the backend sub-profile your profile pulls in.

The validate step runs five independent checks and assembles a report. The check functions are pure — each takes an injected runner / environment / fs accessor so tests can drive them without spawning processes.

CheckWhat it asserts
schema-errorsThe active profile matches the schema: required keys present, no REPLACE_ME placeholders, field formats correct, application hosts end with the chosen domain.
tool-errorsBase CLIs (tofu, ansible-playbook, ssh, curl, skopeo) plus per-provider CLIs (oci, hcloud, doctl, aws) are on PATH.
credential-errorsThe Resend API token works, the Cloudflare zone exists, the OCI config parses, the configured S3/R2 bucket is reachable, the ssh-agent holds compute-pubkey.
image-errorsEvery image under once.applications resolves on its registry via skopeo inspect.
ssh-agent-errorsFor cloud-compute profiles only: SSH_AUTH_SOCK points at an agent that has the private half of compute-pubkey loaded.

Describe

once package describe reports the current state of the deployed profile. It SSHes into the box and queries the running ONCE applications.

What it reports

  • SSH reachability — can we reach user@ip? Does the remote have the once binary?

Provider switching

The renderer is driven by :transform on each render step. The transform pairs a provider value ("oci", "hcloud", "digitalocean", "no-infra") with the Selmer delimiter map. The renderer then copies only the matching subdirectory under tools/<stage>/.

Variable syntax in templates

  • File content uses <{ var }> — interpreted by Selmer at render time.
  • Directory selection uses {{ var }} — the renderer picks tofu/{{ provider-compute }}/.
  • Literal Ansible variables stay as {{ var }} in the rendered output — Ansible interprets them at apply time, after Selmer has already left them alone.

Render-tofu-backend plugin

After each Tofu render step, a pluggable handler injects the remote-state backend HCL (S3 / R2 / local) based on provider-backend. The plugin is registered in tools.{py,ts,clj}; details under BigConfig's pluggable steps.

Don't edit .dist/ The .dist/ directory is generated output. Any change you make is overwritten on the next render. Edit the templates in src/resources/.../tools/ instead.

Clojure: REPL development Clojure only

Every Clojure source file ends with a (comment …) block holding a (debug tap-values …) form. The pattern is: invoke a workflow in the REPL with ::bc/env :repl (instead of :shell), let it capture intermediate opts in tap-values, then inspect the result:

(comment
  (debug tap-values
    (once* "create" options/bb))
  (-> tap-values))

Start the REPL with clojure -A:dev. CIDER picks this up automatically.

Python: interop.py alias bridge Python only

once/python/src/once/interop.py bridges BigConfig's namespaced string keys ("big-config.workflow/params", "big-config.render/profile", …) to friendly aliases ("params", "profile") for the CLI and test boundaries. The sync_aliases, to_bc_opts, and helpers keep both forms in sync so you can write tests against either shape.

TypeScript: NodeNext imports TypeScript only

TypeScript uses NodeNext module resolution, which requires explicit .js extensions in imports even though the source files are .ts:

import { bb } from "./once/options.js";     // note .js, not .ts
import { onceStar } from "./once/package.js";
