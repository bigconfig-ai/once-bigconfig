The State of DevOps Today

Terraform + Ansible + Kubernetes + Helm + GitHub Actions…

Each tool has its own YAML DSL, its own CLI, its own quirks.

We're still in the Separation by Technology era.

Think about it: to deploy an app you touch Terraform HCL, Ansible YAML, Helm charts, GitHub Actions YAML, Dockerfiles… all in different repos, different formats.

The YAML Trap

"Any sufficiently complicated C or Fortran program contains an ad-hoc, informally-specified, bug-ridden, slow implementation of half of Common Lisp."
— Greenspun's Tenth Rule

DevOps has reinvented half of Lisp… in YAML.

Loops in HCL, conditionals in Helm templates, expressions in GitHub Actions —
all without a debugger, compiler, or proper test framework.

The "Merchant of Complexity"

Vendors profit from your internal inefficiency.

  • Proprietary black boxes you can't debug
  • Perpetual consulting for "minor adjustments"
  • Fragmented solutions that require their experts to integrate
  • High switching costs — once you're in, you're stuck

The antidote? Simple over easy. Own your infrastructure.

AI Speaks Terraform Like a Tourist

A 500-line Terraform file is the assembly code of infrastructure —

What is BigConfig SDK?

The SDK is a Clojure/Babashka workflow & template engine for IaC automation.

It powers the BigConfig package model — think npm for infrastructure.

📦 Packages
versioned, composable units
🔒 Client-Side Locking
using Git tags
⚡ Babashka
no server, no daemon
🤖 Agent-Native
designed for LLMs

Architecture at a Glance

Concept What it does
Workflow State-driven engine threading an opts map through pluggable steps
Render Selmer-based template engine (like deps-new, but for infra)
Lock Client-side Atlantis — pessimistic locking via Git tags
Store Redis-backed event-sourcing with ACID guarantees
System Lifecycle management — alternative to Integrant
BigTofu Clojure constructs for generating OpenTofu/Terraform HCL

The Three Environments

The SDK bridges three distinct contexts with one language:

🐚 Shell 🔄 REPL 📚 Lib
bb once create Interactive debugging Embed in your control plane
CI/CD pipelines Inspect state at any step Orchestrate from APIs
GitHub Actions No edit-coffee-fail loops Deep automation

Same code, same functions. No rewrite when you move from CLI → API.

The Killer Feature: Invisible Build Step

alias tofu="bb render git-check lock exec git-push unlock-any -- tofu"

One alias replaces Atlantis + Atmos.

render → generate config git-check → verify clean
lock → acquire lock exec → run tofu
git-push → commit result unlock-any → release

On failure, lock stays, changes stay local. Safe by default.

Why Clojure?

  • Data-driven: packages are plain data maps — agents can read, modify, reason without parsing DSLs
  • Immutability: state threaded through steps is never mutated — perfect for debugging
  • Babashka: same Clojure, zero JVM startup penalty — runs like a shell script
  • REPL: freeze time at any workflow step, inspect values, iterate instantly

The Workflow Engine

At the heart: a state-driven engine threading an opts map through steps. 

(->workflow {:first-step ::start
             :wire-fn (fn [step _]
                        (case step
                          ::start [do-thing ::end]
                          ::end   [identity]))
             :next-fn (fn [step next-step opts]
                        (choice {:on-success next-step
                                 :on-failure ::end
                                 :opts opts}))})

Every step receives and returns opts. Branch on exit code. No side-channel state.

Nested Options = No Name Collisions

Composite workflows use namespaced state. 

;; Terraform output → Ansible input, via opts-fn
(defn opts-fn [opts]
  (let [ip (-> (shell {:dir (workflow/path opts ::tool/tofu)}
                      "tofu show --json")
               parse ip)]
    (assoc-in opts [::workflow/params :ip] ip)))

;; Workflow: tofu → ansible → ansible-local
(pipeline [::tool/tofu    ["render -- tofu apply -auto-approve"]
           ::tool/ansible ["render -- ansible-playbook main.yml" opts-fn]])

Swap Hetzner for AWS? Just change the provider. Downstream Ansible stays untouched.

Client-Side Locking (No Atlantis Needed)

Pessimistic locking via Git tags — no server, no daemon.

Step What happens
generate-lock-id Hash of lock keys (env, region, resource)
create-tag Create a Git tag with the lock ID
push-tag Push it — if someone else's tag exists, push fails
unlock-any Force-release any lock (for emergencies)

Reacquiring your own lock succeeds (idempotent). Different owner → hard fail.

Template Engine (Render)

Selmer-based, inspired by deps-new. Generate config files from data. 

{:big-config.render/templates
 [{:template   "tofu"
   :target-dir ".dist/tofu-{{profile}}"
   :transform  [["tofu" :raw]
                ["templates" "tofu"]]}]}
  • Template files with {{ variables }} → rendered output
  • Custom delimiters for EDN: < > avoids Selmer conflicts
  • Whitespace control: {{- var -}}
  • Binary files bypass rendering (images, etc.)

Get Started in 5 Minutes

# 1. Install Babashka
curl -s https://raw.githubusercontent.com/babashka/babashka/master/install | bash

# 2. Clone the once package
git clone https://github.com/bigconfig-ai/once && cd once

# 3. Configure your providers
#    (Cloudflare API token, Hetzner/OCI credentials as BC_PAR_ env vars)

# 4. Deploy!
bb once create

# 5. SSH into your new server
ssh once

# 6. Tear down when done
bb once delete
