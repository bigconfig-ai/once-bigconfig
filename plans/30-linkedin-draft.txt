You can now scaffold BigConfig packages with Claude Code skills in TypeScript, Python, and Clojure.

Starting from a blank directory is the wrong default for operational packages.

The hard part is not creating files.

The hard part is getting the package boundary right:

✅ language-native manifest
✅ root run file
✅ validate + build verbs
✅ packaged resources
✅ tests
✅ BC_PAR_* overrides
✅ bc-pkg-compatible shape

So BigConfig now has three skills:

• create-ts-bigconfig-package
• create-py-bigconfig-package
• create-clj-bigconfig-package

Each one scaffolds the smallest real BigConfig package in that language.

The skills were built and verified with the same agentic loop they enable:

Generate a throwaway package.
Run tests.
Run package validate.
Run package build.
Force a validation failure.
Fix the template.
Repeat.

Skills teach the agent how to create the package.
BigConfig packages give humans, agents, shells, and CI an executable interface.

Try the skills.
