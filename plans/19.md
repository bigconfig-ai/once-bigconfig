# Plan 19 — Convert the site to light mode everywhere

## Source reality check

Read the current source before implementing this plan. Re-read on 2026-05-28.

The original plan only said:

> Change the theme to light mode everywhere.

Current project state:

- `src/styles/global.css` only imports Tailwind v4 (`@import "tailwindcss";`). There is no shared theme token layer, no Tailwind config, and no existing light/dark theme switcher.
- Most marketing pages hard-code a dark theme directly in Tailwind classes and local CSS, especially `bg-neutral-950`, `bg-neutral-900/*`, `border-neutral-800`, `text-white`, `text-neutral-100`, `text-neutral-300/400/500`, and dark radial backgrounds.
- The dark marketing/page shells to convert are:
  - `src/pages/index.astro`
  - `src/pages/once.astro`
  - `src/pages/walter.astro`
  - `src/pages/clickhouse.astro`
  - `src/pages/marketplace.astro`
  - `src/pages/talk/index.astro`
  - `src/layouts/BlogLayout.astro` (affects blog index, post pages, tag pages, author pages, and `404.astro`)
- The manual is already light:
  - `src/pages/manual.html`
- Most Reveal.js decks already use the white Reveal theme and light code highlighting:
  - `src/pages/talk/agentic-devops/index.html`
  - `src/pages/talk/agentic-devops-in-practice/index.html`
  - `src/pages/talk/agentic-workflow-model/index.html`
  - `src/pages/talk/devops-maturity-levels/index.html`
  - `src/pages/talk/full-agentic-devops-talk/index.html`
- `src/pages/talk/bigconfig-launcher-example/index.astro` is mostly light already, but still has a dark `.command-card` block (`background: #0f172a`). User decision: keep this dark command card as an intentional exception for the standalone launcher slide.
- `src/pages/pi-sessions/deepseek-v4-flash.html` is a standalone static exported Pi session under `src/pages/`. User decision: skip `pi-sessions`; treat it as generated/static content outside the light-theme conversion scope.
- `src/components/ExternalLink.astro` contains a dark-mode hover variant and typo-like class:

  ```astro
  hover:dark:text-white hover:text-back
  ```

  This should be simplified for the light theme.
- Logo imports are theme-sensitive:
  - Cyan/blue dark pages currently import `~/assets/logo-light.svg`.
  - Yellow pages currently import `~/assets/logo-yellow.svg`.
  - `~/assets/logo-dark.svg` exists and is already used by the light launcher slide.

## Goal

Make the public website render as a light theme by default everywhere in scope, with no forced dark page chrome.

Desired visual direction:

- Page background: white or very light slate/neutral.
- Main text: dark ink (`slate-900` / similar).
- Muted text: readable slate/neutral grays (`slate-600` / similar).
- Cards, nav dropdowns, forms, stat grids, tab panels, blog cards, and command/code cards: white or light tinted surfaces with light borders.
- Exception: the dark `.command-card` in `src/pages/talk/bigconfig-launcher-example/index.astro` remains dark because the user explicitly approved it.
- Existing brand accents stay recognizable:
  - Cyan/blue pages keep the BigConfig blue/cyan accent family.
  - Marketplace/ClickHouse keep yellow/amber accents and yellow branding.
- No dark-mode toggle and no `prefers-color-scheme` behavior unless requested.

## Non-goals

- Do not redesign page structure or copy.
- Do not change routes, blog pagination, RSS, redirects, or analytics.
- Do not edit `pnpm-lock.yaml` manually.
- Do not edit generated `dist/` output.
- Do not replace Reveal.js decks with Astro layouts unless separately requested.
- Do not convert `src/pages/pi-sessions/**`; it is intentionally out of scope.

## User decisions

1. Skip `src/pages/pi-sessions/**`; do not include generated Pi session pages in the conversion.
2. Convert command/code cards to light surfaces in normal site pages.
3. Keep the dark command card in `src/pages/talk/bigconfig-launcher-example/index.astro` as the one approved exception.
4. Keep Marketplace and ClickHouse yellow/amber branding and `logo-yellow.svg`.
5. Use a small refactor: add shared light-theme tokens/utilities in `src/styles/global.css` to reduce repeated per-page color mappings.

## Implementation direction

1. Add shared light-theme tokens/utilities.
   - Extend `src/styles/global.css` with a small `@layer base` / `@layer components` refactor instead of repeating all color mappings inline.
   - Suggested CSS variables:
     - `--bc-bg`, `--bc-bg-soft`, `--bc-surface`, `--bc-surface-muted`
     - `--bc-text`, `--bc-text-muted`, `--bc-border`
     - `--bc-accent`, `--bc-accent-hover`, plus yellow/amber variants for Marketplace/ClickHouse if helpful
   - Suggested reusable classes, only where they reduce duplication:
     - `.bc-page-light`
     - `.bc-site-header`
     - `.bc-site-card`
     - `.bc-site-panel`
     - `.bc-muted`
     - `.bc-code-card`
   - Use Tailwind defaults where practical:
     - Background: `bg-white` or `bg-slate-50`
     - Main text: `text-slate-950` / `text-slate-900`
     - Muted text: `text-slate-600` / `text-slate-500`
     - Borders: `border-slate-200`
     - Panels/cards/code cards: `bg-white`, `bg-slate-50`, `bg-white/80`
   - Keep accent colors explicit where they are already part of the brand (`#0652e9`, `#62e1e9`, yellow/amber).

2. Convert shared/layout-level surfaces first.

## Acceptance criteria

- All in-scope pages use light page backgrounds and dark primary text.
- Navigation, dropdowns, mobile menus, cards, forms, tabs, code areas, blog prose, and footers remain readable and accessible.
- Command/code cards are light on normal site pages; only the launcher slide command card may remain dark.
- Logos are visible on light backgrounds.
- Existing interactions still work: mobile menus, docs dropdowns, tabs, launcher controls, copy buttons, and forms.
- `pnpm build` succeeds.
- Remaining dark-related source matches are either removed or explicitly documented as intentional exceptions.
