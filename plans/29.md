## Blog article shape

1. **Open with the slide contrast**
   - What teams ask: deploy, validate, changes, rollback, health.
   - What platforms often expose: `terraform plan/apply`, `helm upgrade`, `kubectl apply`, provider schemas, conventions.

2. **Name the mistake**
   - Those commands are implementation interfaces, not product interfaces.
   - The issue is not that Terraform, Helm, or Kubernetes are bad.
   - The issue is forcing every delivery team and agent to operate at the tool layer.

3. **Explain product-interface thinking**
   - Platform capabilities should answer domain questions.
   - Users should not need a low-level infrastructure curriculum to deploy or inspect an app.

4. **Explain why the old model happened**
   - Custom operational software used to be expensive.
   - Teams exposed tools directly because wrappers, workflows, reports, tests, and adapters were costly.
   - The agent era changes that cost curve.

5. **Introduce agents after the human/team argument**
   - A human can slowly learn conventions; an agent should not infer safety from raw tool access.
   - Agents need an executable contract with explicit read-only and mutating boundaries.

6. **BigConfig turn**
   - This is why BigConfig exists.
   - A BigConfig package keeps Terraform, OpenTofu, Helm, Kubernetes, Ansible, cloud APIs, and scripts inside.
   - It exposes lifecycle and domain verbs outside.

7. **Use concrete verb examples**
   - `package validate`
   - `package build`
   - `package create`
   - `package describe`
   - `package delete`
   - domain verbs such as `rollback`, `backup`, `upgrade`, `audit`, `rotate-keys`, `cost-analysis`

8. **Authority and safety boundary**
   - `validate`, `build`, and `describe` are agent/CI-friendly.
   - `create`, `delete`, `rollback`, and `upgrade` require explicit authority.
   - The interface makes policy easier to enforce because verbs encode intent.

9. **Close with the mantra**
   - `Tools inside. Domain verbs outside.`
   - Link to the Package Spec and the broader infrastructure-programs article.

## Editorial guardrails

- Strongly position BigConfig, but do not write a tool flamewar.
- Do **not** attack Terraform, Helm, Kubernetes, OpenTofu, Ansible, or cloud CLIs.
- The critique is about exposing low-level tools as the user-facing product interface.
- Keep humans/delivery teams central; agents make the problem sharper, but the interface mismatch exists even without agents.
- Make clear that BigConfig keeps existing tools and changes the boundary around them.
- Prefer `package validate`, `package build`, `package create`, `package describe`, and `package delete` over abstract platform language.
- Do not overclaim that every command is safe for agents; safety depends on verb, credentials, and authority policy.
