## Goal

Update the homepage launcher example so users get clear visual feedback about the credentials required by each verb.

Credential categories:

- No credentials: `build`
- Read-only credentials: `validate`, `describe`
- Read-write credentials: `create`, `delete`

## Decisions

1. Keep the existing command-generation behavior intact.
2. The selected credential category is a UI output, separate from the generated command/prompt text.
3. Copy behavior must remain unchanged:
   - Prompt mode copies only the two-line prompt block.
   - Shell mode copies only the raw command without `$ `.
   - No credential note is added to copied text.
4. Keep the current default verb as `validate`.
5. Both packages (`once` and `walter`) use the same credential mapping.
6. Use icons to indicate credential categories.

## Implementation direction

1. Add a small credential metadata map in the inline script:

   ```js
   const credentialRequirements = {
     build: { label: "No credentials", icon: "..." },
     validate: { label: "Read-only credentials", icon: "..." },
     describe: { label: "Read-only credentials", icon: "..." },
     create: { label: "Read-write credentials", icon: "..." },
     delete: { label: "Read-write credentials", icon: "..." },
   };
   ```

2. Update each verb button to show an icon based on its credential category:
   - `build`: no credentials icon
   - `validate`, `describe`: read-only credentials icon
   - `create`, `delete`: read-write credentials icon
3. Add a UI-only credential output near the generated command/prompt, for example in the command card header or directly above the `<pre>` block.
4. Update that credential output whenever `state.verb` changes.
5. Do not change `getDisplayText()`, `getCopyText()`, or the command string format except as needed for refactoring.
