Using infrastructure is not developing infrastructure. 🧭

But in many Terraform workflows, both jobs look the same:

1. 📥 clone the Terraform repo
2. ✏️ edit files
3. 🚀 run Terraform

That is fine for package authors.
It is a bad interface for package consumers.

A delivery team changing one app/environment should operate a package instance:

- 🎯 edit instance-level intent
- ✅ run package validate create
- 🔎 inspect generated artifacts when needed

A platform team developing reusable infrastructure should work in the package source:

- 🧱 edit workflows, templates, validation, reports
- 🏗️ render artifacts
- 🔧 run the lower-level tool loop
- 📌 test local and pinned package flows

Terraform/OpenTofu can still be inside the package.
It just should not be the first interface every delivery team and every agent has to learn.

The rule is simple:

🟦 If the change is about this instance, edit the package instance repo.
🟧 If the change is about how every instance works, edit the package source repo.

That separation is what turns infrastructure from a shared implementation folder into a package people and agents can safely operate.
