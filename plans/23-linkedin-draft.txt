A package manager for agents needs a package spec.

I published the BigConfig Package Spec as a practical implementation guide for package authors.

The goal is simple:
make operational knowledge runnable by agents, humans, shells, and CI without turning every package into a custom snowflake.

The contract is intentionally small:

✅ one root manifest
✅ one root run file
✅ installable code and resources
✅ GitHub SHA pinning
✅ local path development
✅ lifecycle verbs: validate, build, create, describe, delete
✅ generated artifacts that can be inspected outside the conversation

That last part matters.

Agents should not reinterpret runbooks with production credentials.

They should call executable procedures with clear authority boundaries.

An agent can run validate.
A CI job can run build.
A human can keep create and delete behind review.

Same package.
Same lifecycle.
Same contract.

BigConfig packages are like Skills, but executable.
