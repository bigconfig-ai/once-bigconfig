# Plan 13 — Homepage launcher example

## Context read

- Read `src/pages/manual.html`.
  - The manual already documents `bc-pkg` launcher usage for `uvx` and `npx`.
  - The manual has a sticky language switcher implemented with plain HTML/CSS/JS and `localStorage`.
  - The launcher examples currently include TypeScript, Python, and Clojure targets.
- Read `src/pages/index.astro`.
  - The homepage uses Astro only, Tailwind utility classes, and local `Tabs` / `TabItem` components for the existing deploy code sample.
  - It already has a dark `code-tabs` visual style and a small inline script for mobile navigation.

## Goal

Add a new interactive code-example section to `src/pages/index.astro` where users can choose:

1. Launcher: `uvx` or `npx`
2. Target language: TypeScript, Python, or Clojure

The code snippet updates based on both inputs.

## Required output mapping

| Launcher | Target language | Snippet |
|---|---|---|
| `uvx` | TypeScript | `uvx bc-pkg bigconfig-ai/once@typescript package validate` |
| `uvx` | Python | `uvx bc-pkg bigconfig-ai/once@python package validate` |
| `uvx` | Clojure | `uvx bc-pkg bigconfig-ai/once@clojure package validate` |
| `npx` | TypeScript | `npx bc-pkg bigconfig-ai/once@typescript package validate` |
| `npx` | Python | `npx bc-pkg bigconfig-ai/once@python package validate` |
| `npx` | Clojure | `npx bc-pkg bigconfig-ai/once@clojure package validate` |

## Proposed implementation

1. In `src/pages/index.astro`, add a small command data structure near the existing `planMd`, `bbEdn`, and `runSh` constants, or encode the six command strings in the inline browser script.
2. Add a new section to the homepage, likely near the existing `#deploy` section, with:
   - A short heading explaining that users can validate a Once package with either launcher.
   - A segmented control / button group for launcher choice: `uvx`, `npx`.
   - A segmented control / button group for target language choice: `TypeScript`, `Python`, `Clojure`.
   - A single `<pre><code>` block whose text changes when either control changes.
3. Implement the interaction with plain inline JavaScript in the existing `<script is:inline>` block:
   - Track selected launcher and selected language independently.
   - Update the code block text from the mapping above.
   - Update button selected styles and ARIA attributes (`aria-selected`, `role="tab"` or `aria-pressed`).
4. Reuse the existing dark homepage visual language:
   - Tailwind utility classes for the section and controls.
   - Existing `code-tabs` styles where practical, or a small dedicated style if nested tabs are awkward.
5. Ensure the section works without any framework hydration and remains accessible with keyboard focus styles.
6. Run `pnpm build` after editing.

## Decisions

- Place the new section immediately before the existing `#deploy` section.
- Write section copy around BigConfig's support for TypeScript, Python, and Clojure targets through either launcher.
- Default selection: `npx + TypeScript`.
- Do not persist selection in `localStorage`; reset on each page load.
- Do not add a new navbar item.
- Display the command with a shell prompt prefix (`$ `).
- Add a “Copy” button for the generated command.

## Updated implementation notes

1. Add the new section before `<section id="deploy" ...>` in `src/pages/index.astro`.
2. Use an ID such as `launcher-example` for scripting, but do not expose it in the top navigation.
3. Initial rendered command should be:

   ```sh
   $ npx bc-pkg bigconfig-ai/once@typescript package validate
   ```

4. The copy button should copy the command without the prompt prefix by default:

   ```sh
   npx bc-pkg bigconfig-ai/once@typescript package validate
   ```

   If implementation simplicity is preferred, copying the visible string with `$ ` is acceptable, but copy-without-prompt is preferred.
5. Keep the interaction client-side only with inline JavaScript; no Astro hydration or framework state.
