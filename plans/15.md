# Plan 15 — Add package and verb choices to homepage launcher example

## Source reality check

Read `src/pages/index.astro` before updating this plan.

Current `#launcher-example` state in the source:

- The section exists on the homepage.
- It currently has three choice groups:
  1. Launcher: `uvx` or `npx`
  2. Target language: TypeScript, Python, or Clojure
  3. Environment: `Shell` or `Prompt`
- Current defaults in the source are:
  - Launcher: `npx`
  - Target language: `typescript`
  - Environment: `prompt`
- The rendered default prompt is currently:

  ```md
  - run npx bc-pkg bigconfig-ai/once@typescript package validate
  - iterate on failure
  ```

- The current JavaScript builds the command with a hard-coded package and verb:

  ```js
  `${state.launcher} bc-pkg bigconfig-ai/once@${state.language} package validate`
  ```

- Current copy behavior copies `getDisplayText()` exactly as rendered. That means:
  - Prompt mode copies the two-line prompt block.
  - Shell mode copies `$ {command}` including the `$ ` prefix.
- The older context about a `#deploy` section and nav links to `#deploy` is stale for the current `src/pages/index.astro`; no `#deploy` section is present in this file.

## Goal

Update the homepage launcher example so users can choose five inputs:

1. Launcher: `uvx` or `npx`
2. Package: `bigconfig-ai/once` or `bigconfig-ai/walter`
3. Target language: TypeScript, Python, or Clojure
4. Verb: `validate`, `build`, `create`, `describe`, `delete`
5. Environment: `Shell` or `Prompt`

Let `command` be the selected launcher/package/language/verb command without a shell prompt prefix:

```text
{launcher} bc-pkg {package}@{language} package {verb}
```

Default command, keeping the existing default environment (`Prompt`) and using new-control defaults `bigconfig-ai/once` and `validate`:

```text
npx bc-pkg bigconfig-ai/once@typescript package validate
```

## User decisions

- Default environment stays `Prompt`.
- Copy behavior:
  - Shell mode copies the raw command without `$ `.
  - Prompt mode copies the full two-line prompt.
- Rewrite the launcher example intro text to mention package and verb selection.
- Package button labels should be `bigconfig-ai / once` and `bigconfig-ai / walter`; generated commands should still use `bigconfig-ai/once` and `bigconfig-ai/walter` without spaces.
- Verb order is exactly `validate`, `build`, `create`, `describe`, `delete`, with `validate` as the default.

## Environment behavior

### Shell mode

Shell mode should render:

```sh
$ {command}
```

Example:

```sh
$ npx bc-pkg bigconfig-ai/once@typescript package validate
```

### Prompt mode

Prompt mode should render an agent-ready instruction using the same command without `$ `:

```md
- run {command}
- iterate on failure
```

Example:

```md
- run npx bc-pkg bigconfig-ai/once@typescript package validate
- iterate on failure
```

## Proposed implementation steps

1. In `src/pages/index.astro`, rewrite the launcher example intro copy so it mentions choosing a launcher, package, target language, verb, and output environment.
2. Add a new `Package` choice group after `Launcher` with two buttons:
   - Label `bigconfig-ai / once`, `data-package="bigconfig-ai/once"`, default `aria-pressed="true"`
   - Label `bigconfig-ai / walter`, `data-package="bigconfig-ai/walter"`, default `aria-pressed="false"`
3. Keep the `Target language` choice group as-is.
4. Add a new `Verb` choice group after `Target language` with five buttons in this exact order:
   - `data-verb="validate"`, default `aria-pressed="true"`
   - `data-verb="build"`
   - `data-verb="create"`
   - `data-verb="describe"`
   - `data-verb="delete"`
5. Keep the existing `Environment` choice group and keep `Prompt` as the default.
6. Update the inline script state, for example:

   ```js
   const state = {
     launcher: "npx",
     packageName: "bigconfig-ai/once",
     language: "typescript",
     verb: "validate",
     environment: "prompt",
   };
   ```

7. Query and bind the new button groups:
   - `const packageButtons = launcherExample.querySelectorAll("[data-package]");`
   - `const verbButtons = launcherExample.querySelectorAll("[data-verb]");`
8. Update `getCommand()` to use selected package and verb:

   ```js
   const getCommand = () =>
     `${state.launcher} bc-pkg ${state.packageName}@${state.language} package ${state.verb}`;
   ```

9. Add a copy-text helper so Shell copies the raw command while Prompt copies the rendered two-line prompt:

   ```js
   const getCopyText = () =>
     state.environment === "prompt" ? getDisplayText() : getCommand();
   ```

10. Update the copy handler to call `copyText(getCopyText())` instead of `copyText(getDisplayText())`.
11. Add click handlers for package and verb choices using the existing `updateButtons()` helper.
12. Update the static initial `<code id="launcher-command">` contents to match the default state.
13. Confirm `aria-pressed`, `aria-controls`, labels, and keyboard/focus behavior remain consistent for all choice groups.
14. Confirm mobile layout still works with five choice groups.
15. Run `pnpm build`.

## Acceptance criteria

- All choice groups render in this order: Launcher, Package, Target language, Verb, Environment.
- The command updates for every selected combination.
- Shell mode displays `$ {command}`.
- Prompt mode displays:

  ```md
  - run {command}
  - iterate on failure
  ```

- The command label remains `shell command` in Shell mode and `agent prompt` in Prompt mode.
- Copy behavior is:
  - Shell mode copies the raw command without `$ `.
  - Prompt mode copies the full two-line prompt.
- Package buttons display `bigconfig-ai / once` and `bigconfig-ai / walter` with spaces around `/`.
- Accessibility state stays correct: exactly one button per group has `aria-pressed="true"`.
- `pnpm build` passes.
