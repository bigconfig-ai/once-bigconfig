This is exactly the right Day 2 infrastructure problem.

Terraform can create the resource.
But the workflow usually continues after apply:

→ read the output
→ update DNS
→ render config
→ configure the host
→ purge cache
→ report what changed

A YAML workflow is one answer.

BigConfig takes a different route: make the whole thing a package.

The BigConfig SDK supports TypeScript, Python, and Clojure. The article example uses TypeScript.

Code-first: write the workflow with tests and normal package structure.

Local-first: run it from a laptop, CI, shell, or agent session before needing a hosted control plane.

Agent-first: expose stable verbs like package validate, build, create, describe, delete.

The key handoff is Terraform output → normalized package params → later modules.

So DNS consumes `ip` or `public-ip`, not `hcloud_server.node1.ipv4_address` vs `oci_core_instance.public_ip` vs whatever another provider calls it.

Keep Terraform.
Stop making Terraform the whole interface.
Package the Day 2 workflow.
