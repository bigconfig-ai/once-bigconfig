## Review findings

- The recommended implementation from the previous plan has effectively been
  implemented: custom CSS tooltip, no extra JavaScript, hover + keyboard focus,
  `pointer-events: none`, and the `data-package` attribute remains on the real
  button.
- The implemented scope is broader than the old acceptance criteria. The old
  plan said the popup should not appear for `bigconfig-ai / walter` or
  `your / package` unless requested separately, but current source gives both of
  those buttons tooltips as well.
- The implemented scope is also broader across routes. The old default was
  homepage-only; current source adds matching tooltips to the standalone launcher
  talk too.
- The tooltip CSS and copy are duplicated between the homepage and the talk. That
  is acceptable for a standalone talk page, but future copy/style changes need to
  be applied in both files unless a shared component/refactor is introduced.
- The `walter` tooltip is much longer than the `once` and `your / package`
  tooltips. It may feel dense in the compact launcher UI, especially in the talk
  slide.
- The current implementation is static and non-interactive, so it does not need
  Escape-key handling or popover state. It should not affect package selection,
  copy behavior, selected state, or credentials.

## Acceptance criteria

Decision-dependent acceptance criteria:

- The `bigconfig-ai / once` popup appears on hover and keyboard focus.
- Tooltip scope matches the user's decision:
  - all three package buttons on both routes, or
  - `once` only, or
  - homepage only.
- Every package button that participates in command generation keeps its
  `data-package` attribute on the actual `<button>` element.
- Clicking package buttons still updates the generated command correctly.
- `aria-pressed` updates still work for package selection.
- Copy behavior and credential feedback are unchanged.
- `pnpm build` passes after dependencies are installed.
