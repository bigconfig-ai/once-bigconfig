# Plan 20 — Add a hover popup for the `bigconfig-ai / once` package button

## Source reality check

Read `src/pages/index.astro` on 2026-05-29.

Current homepage state:

- The target UI is in `src/pages/index.astro` inside the `#launcher-example` section.
- The visible button text is:

  ```text
  bigconfig-ai / once
  ```

- The target button is the first button in the **Package** choice group:

  ```astro
  <button
    type="button"
    class="command-option"
    data-package="bigconfig-ai/once"
    aria-pressed="true"
    aria-controls="launcher-command"
  >bigconfig-ai / once</button>
  ```

- The launcher JavaScript selects package buttons with:

  ```js
  const packageButtons = launcherExample.querySelectorAll("[data-package]");
  ```

  So the tooltip implementation must keep the `data-package="bigconfig-ai/once"` attribute on the actual `<button>`.
- `.command-option` styling already lives in the inline `<style is:global>` block in `src/pages/index.astro`.
- There is no existing tooltip/popover component or utility class in the homepage source.
- This is a static explanatory popup; it does not need to affect command generation, copy behavior, selected state, or credentials.

## Goal

Add this explanatory popup to the homepage button `bigconfig-ai / once`:

```text
once is a package that automatically sets up everything needed to run a web application on a cloud server. It provisions the server, configures the domain name, sets up email sending, and deploys the app — in the right order, all with one command.
```

## Review notes

- A native `title="..."` attribute would be the smallest implementation, but it is hard to style, inconsistent across browsers, weak on touch devices, and not ideal for keyboard/accessibility.
- Recommended implementation: a small custom CSS tooltip in `src/pages/index.astro`, visible on hover and keyboard focus, with no extra JavaScript.
- Because the target is a button inside an interactive choice group, the implementation should not intercept clicks or change the existing package-selection behavior.
- The original plan text includes extra spacing between sentences; normalize it to single spaces unless exact whitespace is required.

## Questions for the user

1. Should this be a custom styled tooltip (recommended) or a native browser `title` tooltip?
2. Should the popup appear on keyboard focus as well as hover? Recommended: yes.
3. Should this be homepage-only, or should the same tooltip also be added to the standalone launcher talk at `src/pages/talk/bigconfig-launcher-example/index.astro`?
4. Do you want the visual style to be a dark tooltip bubble above the button, or a light card-style popup matching the homepage cards?
5. Should only `bigconfig-ai / once` get explanatory text, or should `bigconfig-ai / walter` and `your / package` also get tooltips later?

## Proposed default decisions if the user does not specify otherwise

1. Use a custom CSS tooltip, not the native `title` attribute.
2. Show it on hover and on keyboard focus (`:focus-within`).
3. Scope the change to `src/pages/index.astro` only.
4. Use the normalized popup copy shown in the Goal section.
5. Style the popup as a compact dark slate bubble above the button with a small arrow, high z-index, max width around `20rem`, and `pointer-events: none` so it cannot block clicks.
6. Add no JavaScript.

## Implementation direction

1. Add local tooltip CSS to the existing `<style is:global>` block in `src/pages/index.astro` near the existing `.command-option` styles.

   Suggested class structure:

   ```css
   .package-tooltip-trigger {
     position: relative;
     display: inline-flex;
   }

   .package-tooltip-bubble {
     pointer-events: none;
     position: absolute;
     left: 50%;
     bottom: calc(100% + 0.75rem);
     z-index: 60;
     width: max-content;
     max-width: min(20rem, calc(100vw - 2rem));
     transform: translateX(-50%) translateY(0.25rem);
     border-radius: 0.875rem;
     background: #0f172a;
     color: #ffffff;
     padding: 0.75rem 0.875rem;
     font-size: 0.8125rem;
     line-height: 1.45;
     text-align: left;
     box-shadow: 0 18px 40px rgb(15 23 42 / 0.22);
     opacity: 0;
     visibility: hidden;
     transition: opacity 150ms ease, transform 150ms ease, visibility 150ms ease;
   }

   .package-tooltip-bubble::after {
     content: "";
     position: absolute;
     left: 50%;
     top: 100%;
     transform: translateX(-50%);
     border-width: 0.4rem 0.4rem 0;
     border-style: solid;
     border-color: #0f172a transparent transparent;
   }

   .package-tooltip-trigger:hover .package-tooltip-bubble,
   .package-tooltip-trigger:focus-within .package-tooltip-bubble {
     opacity: 1;
     visibility: visible;
     transform: translateX(-50%) translateY(0);
   }
   ```

   Optional: add a `prefers-reduced-motion` media query to remove the transition for users who prefer reduced motion.

2. Wrap only the `bigconfig-ai / once` button in a tooltip trigger and add an accessible description.

   Suggested markup shape:

   ```astro
   <span class="package-tooltip-trigger">
     <button
       type="button"
       class="command-option"
       data-package="bigconfig-ai/once"
       aria-pressed="true"
       aria-controls="launcher-command"
       aria-describedby="package-once-tooltip"
     >bigconfig-ai / once</button>
     <span id="package-once-tooltip" role="tooltip" class="package-tooltip-bubble">
       once is a package that automatically sets up everything needed to run a web application on a cloud server. It provisions the server, configures the domain name, sets up email sending, and deploys the app — in the right order, all with one command.
     </span>
   </span>
   ```

3. Confirm the existing package selection logic still works.
   - `querySelectorAll("[data-package]")` should still find the button.
   - Clicking the button should still set `state.packageName = "bigconfig-ai/once"`.
   - `aria-pressed` updates should still work.

4. Verify with:

   ```bash
   pnpm build
   ```
