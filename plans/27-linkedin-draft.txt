☸️ Crossplane makes Kubernetes the public runtime for platform operations.

📦 BigConfig replaces that boundary with executable packages.

That is the whole difference. 🔑

With Crossplane, your platform abstraction becomes Kubernetes resources: ☸️

- CRDs
- claims
- composites
- managed resources
- providers
- RBAC
- conditions
- events
- finalizers
- reconciliation loops

With BigConfig, your platform abstraction becomes commands: 📦

✅ package validate
🚀 package create
🔎 package describe
🧹 package delete

The package can still use Kubernetes.
It can still run Helm.
It can still render Terraform/OpenTofu.
It can still run Ansible.
It can still call cloud APIs.

But those tools are implementation details.

The public interface is the package.

This matters even more with agents. 🤖

The control-plane API is no longer the holy grail of DevOps.

A control plane is just a backend application. If you need one, wrap the BigConfig package in a backend app later and reuse the same package logic.

But do not start API-first and then add MCP just so an agent can call your API.

If the agent and the package can run on the same computer, skip the API/MCP abstraction entirely.

Use containers as credential boundaries: 🔐

- agent container: advisory/read-only credentials
- operator container: mutating credentials for the fix

Keep server-side automation for loops that do not require a human in the loop, like autoscaling.

Keep human-guided diagnosis, validation, remediation, and package operation close to the agent and operator.

That is why BigConfig replaces Crossplane: ⚡

Crossplane turns infrastructure into Kubernetes APIs.
BigConfig turns infrastructure into packages you can run.
